# Руководство по работе с репозиторием

## Назначение и границы проекта

Этот репозиторий — содержимое каталога `/local` для существующей установки
1С-Битрикс, а не самостоятельное приложение. В нём нет ядра Bitrix, document
root, базы данных, инфоблоков, меню и большинства страниц CMS. Поэтому итоговый
HTML может содержать внешние обёртки и данные, которых нет в Git.

- `php_interface/` — bootstrap локального кода, конфигурация установки и общие
  функции безопасности.
- `components/csr43/` — все собственные компоненты проекта, включая
  `cookie.manager`, `bvi.version`, списки файлов/ссылок и `news.categories`;
  в Bitrix они вызываются с пространством имён `csr43:`.
- `templates/csr43_site/` — основной шаблон сайта, глобальные стили/скрипты и
  переопределения шаблонов штатных компонентов Bitrix.
- `js/analytics/` — аналитика, загружаемая только после согласия на cookie.
- `examples/` — примеры вызова собственных и штатных компонентов. Это
  документация для переноса в CMS, а не исполняемые страницы этого checkout.

У инструкций этого файла область действия — весь репозиторий.

## Перед началом работы

- Сначала проверьте `git status --short`. Сохраняйте чужие и несвязанные
  изменения; не форматируйте файлы целиком без необходимости.
- Для полного списка файлов используйте `git ls-files` или `rg --hidden`:
  метаданные компонентов находятся в скрытых `.description.php`,
  `.parameters.php` и каталогах `.default/`.
- Не коммитьте, не отправляйте изменения, не развёртывайте их на сервере и не
  очищайте кеш Bitrix без прямого указания пользователя.
- Не делайте вывод о поведении страницы только по этому checkout: часть
  разметки и все данные инфоблоков принадлежат установке Bitrix.

## Среда и зависимости

- Код требует PHP 8.0+ и API 1С-Битрикс (`$APPLICATION`, `CBitrixComponent`,
  `CIBlock*`, `CFile`, `SITE_TEMPLATE_PATH` и т. п.).
- Модуль `iblock` подключается через `Bitrix\Main\Loader` до использования его
  API.
- Bootstrap 5.3, Bootstrap Icons, Font Awesome, jQuery 3.6 и Fancybox 5 лежат в
  репозитории и регистрируются в `templates/csr43_site/header.php`.
- Сборки через Composer/npm нет. Нет PHPUnit, PHPStan, PHPCS, ESLint,
  Stylelint, CI-конфигурации или локального тестового стенда.
- Сторонние minified-файлы, sourcemaps и шрифты считаются vendored-кодом и не
  редактируются вручную без отдельной задачи на обновление зависимости.
- `components/csr43/bvi.version/templates/.default/dist/` — поддерживаемая в
  проекте собственная версия BVI. Изменения вносите в читаемый
  `dist/js/bvi.js`, после чего пересобирайте `bvi.min.js` и `bvi.min.js.map`;
  сжатый файл и его карту не редактируйте вручную.

## Архитектура Bitrix

- Каждый исполняемый PHP-файл Bitrix должен начинаться guard-проверкой
  `B_PROLOG_INCLUDED`.
- В шаблонах компонентов включайте `$this->setFrameMode(true)`, если компонент
  допускает динамические фреймы.
- Запросы и существенную подготовку данных размещайте в `component.php` или
  `result_modifier.php`; `template.php` оставляйте преимущественно слоем
  представления. Не возвращайте запросы маршрутов в
  `custom_bus_list/template.php`: их массовая подготовка находится в соседнем
  `result_modifier.php`.
- Нормализуйте `$arParams` и `$arResult`, проверяйте `is_array()` и используйте
  ранний `return` для пустых или невалидных данных.
- ID приводите к положительным целым, лимиты ограничивайте, значения `Y/N`
  проверяйте строго, а `CACHE_TYPE` разрешайте только из `A`, `Y`, `N`.
- В публичных запросах к инфоблокам сохраняйте фильтры `ACTIVE`, при
  необходимости `ACTIVE_DATE`, и всегда учитывайте `CHECK_PERMISSIONS => 'Y'`.
  Если результат зависит от прав, не отключайте `CACHE_GROUPS` либо явно
  включайте отсортированные группы пользователя в дополнительный ключ кеша,
  как это делает `csr43:news.categories`.
- Сохраняйте административные действия `AddEditAction`, `AddDeleteAction` и
  `GetEditAreaId` при изменении списков и карточек.
- Не переименовывайте компоненты, шаблоны, параметры или коды свойств
  инфоблоков без проверки их вызовов в CMS, которой нет в репозитории.
- При перемещении собственного компонента обновляйте вместе его вызовы в
  `header.php`, `footer.php`, шаблонах и `examples/`. Для текущего расположения
  корректные имена — `csr43:bvi.version`, `csr43:cookie.manager`,
  `csr43:files.list`, `csr43:links.list` и `csr43:news.categories`.
- Для переиспользуемых текстов компонентов используйте `GetMessage()` или
  `Loc::getMessage()` и соответствующий `lang/ru/`.

## Безопасность и вывод

Считайте недоверенными значения из `$arParams`, `$arResult`, инфоблоков,
`$_GET`, `$_SERVER` и `get_info()`. Последняя функция ничего не экранирует.

Используйте функции из `php_interface/include/security.php`:

- `site_string()` и `site_string_list()` — нормализация scalar-значений;
- `site_plain_text()` — обычный текст без HTML;
- `site_url()` — URL с явным набором допустимых схем, в том числе с безопасной
  нормализацией IDN-хоста;
- `site_is_external_http_url()` — проверка уже нормализованного URL на внешнюю
  HTTP(S)-ссылку;
- `site_template_image_url()` — имя файла из конфигурации в каталоге
  `templates/csr43_site/images/`; функция не принимает произвольный путь;
- `site_css_classes()` и `site_menu_type()` — динамические CSS-классы и типы
  меню;
- `site_css_url()` — URL для CSS-контекста;
- `site_path_is_excluded()` — проверка текущего пути по списку исключённых
  разделов с учётом вложенных страниц;
- `site_safe_html()` — только намеренно разрешённый форматированный HTML;
- `site_safe_pagination_html()` — только готовая разметка штатной пагинации с
  ограниченным набором тегов и ARIA-атрибутов, не общий HTML-контент.

Правила контекстного вывода:

- обычный текст и HTML-атрибуты после нормализации выводите через
  `htmlspecialcharsbx()`;
- URL сначала пропускайте через `site_url()`, затем экранируйте для атрибута;
- `tel:` и `mailto:` разрешайте явно в аргументах `site_url()`;
- имена изображений шаблона из `get_info()` пропускайте через
  `site_template_image_url()`, а URL контентных изображений — через
  `site_url()`;
- поля Bitrix вида `~NAME`, `~PREVIEW_TEXT`, `~DETAIL_TEXT` не выводите напрямую:
  преобразуйте их в plain text либо пропустите через `site_safe_html()`;
- динамические имена тегов и классы должны выбираться только из allowlist;
- для PHP-данных внутри JavaScript/JSON используйте `json_encode()` с
  `JSON_HEX_TAG | JSON_HEX_AMP | JSON_HEX_APOS | JSON_HEX_QUOT` и обработкой
  невалидного UTF-8;
- внешняя ссылка с `target="_blank"` обязана иметь
  `rel="noopener noreferrer"`;
- новые POST/AJAX-операции должны проверять Bitrix session/CSRF-токен и права.

## Конфигурация и layout

- `php_interface/init.php` подключает активный `include/info.php`, затем
  security- и canonical-helper'ы.
- `include/info_tr.php` — альтернативная конфигурация и сейчас не подключена.
  Не синхронизируйте её автоматически и не подключайте одновременно с
  `info.php`: оба файла объявляют одинаковые константу и функции.
- Не хардкодьте сведения об организации, URL, контакты и типы меню в новых
  местах; используйте `get_info()`.
- `header.php` условно открывает layout-контейнеры, а `footer.php` закрывает их.
  Условия на `layout_excluded_pages` и 404 должны оставаться симметричными в
  обоих файлах; пути проверяйте через `site_path_is_excluded()`.
- `style.css` и `script.js` рядом с шаблоном компонента подключаются Bitrix
  автоматически. Глобальные зависимости регистрируйте через
  `SetAdditionalCSS()`/`AddHeadScript()`, не дублируйте `<link>` и `<script>`.
- Локальные шаблоны `bitrix:search.page` и `bitrix:system.pagenavigation`
  находятся соответственно в `search.page/.default/` и
  `system.pagenavigation/csr43/`. Пагинация выбирается параметром
  `PAGER_TEMPLATE` родительского компонента, а не отдельным вызовом на странице.

## CSS и система `csr43-glass-*`

Общая система находится в `templates/csr43_site/css/ui/glass.css`.

- Для нового кода используйте только `.csr43-glass-surface`,
  `.csr43-glass-card`, модификаторы `--interactive`/`--stretch`,
  `.csr43-glass-icon` и `.csr43-glass-badge`.
- Не возвращайте точный старый класс `.glass-card` и не создавайте для него
  compatibility alias. Временные `.glass` и `.glass-card-blue` не используйте
  в новом коде и не удаляйте без аудита страниц CMS.
- Вариации карточек задавайте через `--csr43-glass-*` на компонентном классе,
  включая media queries. В собранном Bitrix CSS общий `glass.css` может идти
  после CSS компонента и перекрывать физические свойства равной специфичности.
- Не совмещайте `.csr43-glass-card` и Bootstrap `.row` на одном элементе:
  отрицательные gutters расширят фон. Используйте card-wrapper и вложенную
  `.row`.
- Не применяйте `overflow: hidden` без проверки transform/scale дочерних
  элементов и focus outline.
- Интерактивные состояния должны поддерживать клавиатуру (`:focus-visible`),
  `prefers-reduced-motion` и fallback без `backdrop-filter`.
- Не исправляйте конфликт с Bootstrap случайным `!important`: используйте
  переменные или осмысленно более специфичный селектор, например
  `.btn.component-button`.
- Новые компонентные классы оформляйте в BEM-подобном виде
  `block__element--modifier`; существующие legacy-классы не переименовывайте
  массово.

## Версия для слабовидящих (BVI)

- Общие интеграционные переопределения BVI размещайте в
  `components/csr43/bvi.version/templates/.default/bvi-accessibility.css`.
  Компонентные размеры и переменные оставляйте в `style.css` соответствующего
  шаблона.
- Контентные изображения (фотографии, документы и элементы галерей) выводите
  через `<img>`, а не через `background-image`: BVI автоматически назначает
  таким элементам `.bvi-img` и применяет выбранный режим изображений.
  `background-image` используйте только для декоративного оформления.
- Для `<img>` нормализуйте `src` через `site_url()`, экранируйте атрибут,
  задавайте содержательный `alt` для информативного изображения или пустой
  `alt` для декоративного. При уместности используйте `loading="lazy"` и
  `decoding="async"`.
- BVI задаёт `font-size` элементам через `!important`. Размер декоративной
  иконки внутри `.csr43-glass-icon` задавайте через
  `--csr43-glass-icon-font-size`. Для других иконок фиксированного размера
  используйте `--csr43-fixed-icon-font-size` и добавляйте точечный селектор в
  `bvi-accessibility.css`. Иконки, являющиеся частью текста, без необходимости
  не фиксируйте: они должны масштабироваться вместе с текстом.
- BVI не может назначать служебные классы псевдоэлементам. Цвета и фоны
  `::before`/`::after` в режиме слабовидящих переопределяйте через
  `currentColor` или переменные активной BVI-темы; не оставляйте в них жёсткие
  синие цвета и градиенты.
- Не добавляйте `.bvi-no-styles` для обхода визуального конфликта без проверки
  всех BVI-режимов: этот класс исключает элемент из доступной адаптации.

## JavaScript

- Инициализаторы должны корректно переживать отсутствие ожидаемого DOM или
  внешней библиотеки и не навешивать обработчики повторно.
- Для динамических Bitrix-фреймов поддерживайте и обычную загрузку DOM, и
  `onFrameDataReceived`. В качестве образца используйте
  `custom_discussionslist/script.js`.
- Используйте `data-*` как JS-hooks. Предпочитайте `addEventListener()` новым
  inline-обработчикам.
- Не вставляйте пользовательские данные через `innerHTML`; используйте
  `textContent` и DOM API либо заранее безопасно сформированный PHP-шаблон.
- Сохраняйте keyboard- и ARIA-поведение при изменении меню, collapse, галерей и
  других интерактивных элементов.

## Проверка изменений

Минимум перед передачей результата:

```bash
git diff --check
git status --short
```

Проверка всех отслеживаемых PHP- и JS-файлов в Bash-среде:

```bash
git ls-files -z '*.php' | xargs -0 -n1 php -l
git ls-files -z '*.js' | xargs -0 -n1 node --check
```

Эквивалент для PowerShell:

```powershell
git ls-files '*.php' | ForEach-Object {
    php -l $_
    if ($LASTEXITCODE -ne 0) { throw "PHP lint failed: $_" }
}
git ls-files '*.js' | ForEach-Object {
    node --check $_
    if ($LASTEXITCODE -ne 0) { throw "JS check failed: $_" }
}
```

Перед запуском проверьте наличие `php` и `node` через `Get-Command`/`command -v`.
В репозитории нет собственного toolchain: отсутствующую утилиту отмечайте как
ограничение проверки, а не устанавливайте без запроса пользователя.

Это только синтаксические проверки. Автоматической проверки CSS и полноценного
рендера нет. Для затронутого интерфейса вручную проверьте:

- узкий мобильный экран, tablet и desktop;
- hover, клавиатурный focus и `prefers-reduced-motion`;
- длинные названия, отсутствующие поля/изображения и пустые списки;
- все пять цветовых тем BVI, несколько размеров шрифта и контраст
  фиксированных иконок и псевдоэлементов;
- режимы изображений BVI: цветные, чёрно-белые и скрытые, включая содержимое
  динамических галерей;
- итоговый порядок CSS-бандлов и поведение после очистки кеша Bitrix;
- fallback без `backdrop-filter`, если менялась glass-система.

Сетевую проверку тестовой установки, очистку кеша и деплой выполняйте только по
явному запросу. В итоговом сообщении перечислите изменённые файлы, выполненные
проверки и то, что нельзя было проверить без полноценной установки Bitrix.
